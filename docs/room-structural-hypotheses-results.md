# 结构候选的障碍物校验与裁决证据（2026-09-19）

## 接续状态与复现

上个任务因额度中断，遗留了单对象补图和局部结构池候选实现。旧实现只有在总对象数大于 100 时启用局部结构池，并使用空障碍物列表构建候选；门扇、楼梯线也可能进入该图。

本轮在实际 resolver 入口复现：一个 10×10 围合与横跨外边界的已知障碍物，加上 100 个窗口外无关对象后，会被宽松测试裁决器接受。命令 `bun test src/room-spatial-geometry.test.ts --test-name-pattern 'structural hypotheses cannot'` 修改前失败（得到 accepted），修改后通过。这是合成的错误接受回归，不是六房间识别成功证据。

## 修改

- 用 `src/room-boundary-hypotheses.ts` 集中生成结构候选，替换未完成的内联假设逻辑。移除总对象数大于 100 的启用条件。
- 在常规关系、表面复核和修复轮次后，才提出结构候选。既有候选被拒绝也可以进入该路径。
- 仅从局部 wall/window/column 语义池取证；不将 door/stair/furniture 或已判 opening_boundary/obstacle 对象加入外环图。
- 完整保留已知障碍物作为内环或缺陷，缺陷候选不能进入最终接受选项。
- 固定默认预算：220 个结构对象、1200 个区段、5 个结构候选。不为满足区段预算截取单个对象；记录被截断的覆盖范围。
- 所有结构候选墙段均标为 repair，附带来源、原关系（null 为从未审查）、语义类型和几何警告。历史对象/表面决定保持不变，最终候选选择只批准显示的区段。
- 新模块加入严格回放代码哈希清单；CLI 暴露结构对象和区段预算。

逐对象关系预算仍为 48→96、两轮、32 次请求、48 个表面复核。沿用中断任务已改动的断口范围 2200mm / 48 个候选，因此与 frontier 的 1500mm / 24 个候选不构成单变量对照。结构池的几何检索预算与关系判断预算分开记录，不能称为“只有 96 个图元”。

## 验证

70 项测试与类型检查通过。新增覆盖障碍物被遗漏的 resolver 回归、内环净面积、开口/门扇/楼梯排除、区段预算整对象保留、对象输入顺序，以及未审查结构图元必须经过最终接受/拒绝与精确离线回放。

六个实测报告全部通过严格 CLI 离线回放：仅排除 `replay_source`、`reuse_source`、`fresh_request_count` 三个运行来源字段后，完整报告逐字段一致，回放新增请求均为零。回放目录：`reports/room-v2/structural-reviewed-replay/`。

## 固定六房间实测

运行目录：`reports/room-v2/structural-reviewed-evaluation/`。六房间使用相同输入、代码哈希和预算。156 条决策中新增 37 次、精确复用 119 次，所有请求有效。最终 **0/6 接受**。

| 房间 | 候选面积（㎡） | 结果 |
|---|---|---|
| 资料室 | 14.799 | Jev 拒绝 |
| 登记室 | 0.135, 0.135 | Jev 拒绝 |
| 冷链室 | 无 | 无完整候选 |
| 哺乳室 | 3.657, 3.477 | 障碍物冲突/未决 |
| 接种室 | 无 | 无完整候选 |
| 留观区 | 455.683 | Jev 拒绝 |

资料室的结构池生成 14.799㎡候选，但模型拒绝；登记室的两条候选都约 0.135㎡，不能算作两个不同的正确房间。哺乳室新增 3.477㎡结构候选，因同样的障碍物冲突被几何校验阻止。冷链室、接种室仍无完整候选。

结构池实际检索 170–220 个对象、518–895 个区段。四个房间的结构对象池被 220 上限截断。资料室与登记室的结构池未被对象或区段预算截断，也仍未通过最终裁决。

这轮改善是修复可复现的错误接受路径、补齐候选证据及预算记录；没有证据表明最终识别成功率提高。

## 限制

结构语义只是候选检索依据，不能自动证明房间边界正确。只校验已经识别出的障碍物，未审查障碍物仍可能遗漏。当前结构候选自身不补门洞或绘图断口；复杂轮廓需要后续开口接点取证。缺少独立人工参考边界，接受率不等于准确率。
