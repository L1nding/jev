# 按断口分配检索与相邻区段证据（2026-09-19）

## 变更与验证

原第二轮将所有候选按“距任一断口的最小距离”统一排序。合成回归复现：一处断口周围的密集图元占满两个名额，另一处真实延续线没有进入上下文。

新增 `src/room-context-retrieval.ts`，在原半径、对象数及请求预算下，按断口轮换取出附近候选，再用原距离顺序补齐剩余名额。保留第一轮所有对象及其判断；稳定排序与去重使图元和断口输入顺序不影响该合成案例。检索轨迹记录具体断口、图元与距离，不将其视为批准的房间成员。

第二轮对象关系请求增加相邻已判 boundary/opening_boundary 对象的实际区段，每个候选最多四个邻居、每个邻居两段，提供先前关系与距离。该证据支持端点接在线段中部的情况，不引入虚拟连接，不代替 Jev 的关系选择。这仍是逐图元关系判断，并未实现整组关系的联合选择。

63 项测试、类型检查通过。新增测试覆盖密集区域挤占、输入顺序、保留对象与回退、线段中部接触，以及 resolver 第二轮实际请求中包含邻居区段。端到端合成案例可闭合并精确回放。

## 剩余问题

- 断口来自当前模型选择的图，可能属于误选图元；公平分配并不保证检索到正确墙段。
- 邻居证据有界，只包含先前已选边界；跨实体物理对象身份和成组关系推理仍未完成。
- 已闭合但被拒绝的轮廓，尚未将其边界争议点转为下一轮检索焦点。
- 冷链室、接种室仍没有完整候选。应进一步区分未取证连接、关系排除、开口接点与 face 构建缺陷，不能仅凭无候选断言模型错误。
- 缺少人工参考边界，无法计算真实召回率或准确率。
