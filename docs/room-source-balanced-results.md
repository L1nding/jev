# 区段召回诊断与复核预算分配（2026-09-19）

## 已证实的问题

新增离线诊断脚本 `scripts/audit-room-surface-recall.ts`。读取实测几何和房间报告，验证几何哈希，重建最终对象判断后的边界图和区段复核后的边界图；对照时不加入虚拟连接，不修改 Jev 判断，不接受诊断轮廓。

旧版六房间每间都复核 48 段，但实际参与当前边界图的仅合计 120 段。资料室一个已判 irrelevant 的图元消耗 24 个复核名额，而 260 个仍保留在边界图中的区段未复核。所谓“排除 32 段”中，只有 1 段真正从该房间边界图中移除。

这证明复核预算被复杂候选过多占用，不能证明哪条未复核线就是正确墙线。所有房间局部范围内有 649–879 个原始图元，只有 96 个进入上下文；缺少人工参考边界，目前不能计算真实边界召回率。

## 实施

- 复核槽位按当前边界图与恢复候选 2:1 分配，一侧不足时让另一侧使用剩余名额；保持总计 48 段及原请求预算。
- 每侧按 Source Entity 轮换，防止同一复杂图元的大量区段耗尽名额。原有 seed 距离、缺陷距离及方向多样性仅作为取证排序。
- 请求概览必须包含实际提问的区段，避免远处选中项缺失于概览。
- 统计明确区分 `non_boundary` 选择次数、实际移除数、实际补回数及复核覆盖数。汇总字段从容易误解的 `surfaces_excluded` 改为 `surface_non_boundary_choices`，并增加覆盖详情。
- 几何排序不改变语义成员；只有 Jev 的明确选择能补回或移除区段。

## 验证及后续

59 项测试与类型检查通过。新增失败测试先复现复杂图元挤占预算，再验证公平取样、剩余预算回流、请求概览完整性及不改写 uncertain 决策。

仍有大量边界区段未复核，检索池也未完整覆盖局部图元。下一步应定位与已有边界链连接的未取证图元，并给 Jev 成组上下文，而不是把所有未检查区段默认为正确，也不是按图层直接删除。需要人工参考边界才能确认真正遗漏的墙段及区分检索错误、语义错误和图算法错误。
