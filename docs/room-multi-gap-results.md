# 多断口组合实验（2026-09-19）

## 问题与变更

旧搜索只枚举单连接和双连接，三处独立断口的合成房间无法进入最终选择题。先加入失败测试，再修复搜索：在原有 96 次变体预算中，为以不同连接为起点的兼容连接集合预留一部分预算，然后继续枚举单连接和双连接。连接按稳定 ID 排序，反转输入连接顺序不会改变该合成案例的候选。

这不是穷举，也不是“按几何自动批准”。共享端点、相交和同一开口的互斥 portal 仍不能同时进入集合；所有候选仍必须经过完整空间校验与 Jev 最终接受。几何无效的候选不会交给模型。

另一个回归测试暴露了证据遗漏：planarize 将虚拟连接切成子段后，原来的端点完全匹配会漏列其批准项。现按子段被原始连接覆盖的关系追溯，缺少关联证据的虚拟边不进入候选；未被轮廓使用的独立连接不会一并批准。

## 验证

- 57 项测试通过，类型检查通过。
- 三断口合成房间由无候选变为 100 平方源单位的完整候选，修补记录恰为三个实际使用的连接。
- 覆盖同一开口互斥项、分割后连接证据、反向输入连接顺序与无关修补不被批准。
- 登记室严格离线回放一致，仅排除来源路径及新增请求统计字段。

## 同图纸六房间结果

`reports/room-v2/multi-gap-evaluation/summary.json` 中六房间仍为 **0/6 接受**。资料室、冷链室、接种室无最终候选；哺乳室候选存在障碍物冲突；留观区和登记室原候选仍被 Jev 拒绝。十次联合搜索均达到 96 次预算，没有生成新的合格联合修补候选。

全部复用请求内容完全一致的历史 Jev 响应，共 141 条，新增模型请求 0；这是新算法执行下的开发回归，不是模型独立重复评测。不能宣称真实房间识别改善。

## 结论与限制

“最多两个连接”是已证实的能力缺陷，但不是足以解释并修复这六个真实房间的原因。兼容集合只覆盖部分组合，加入多余连接也可能改变 face 划分；不能据此排除仍有未搜索到的有效组合。

目前不应继续单纯增大组合搜索上限。下一项需要检查区段召回：哪些原始几何进入上下文、哪些被 Jev 保留/剔除、正确闭合链在哪一步丢失。没有人工参考边界之前，不能把未知归为模型判断错误，也不能用面积或闭合自动接受来制造成功。
